# Arduino IDE: Rules for Folders, Files, and Libraries

## 1. Sketch fundamentals (folder and main file)

- A **sketch** is always stored in its own **folder**.
- The **folder name** is the **sketch name**.
- The folder must contain exactly one main `.ino` file whose name matches the folder name:
  - Folder: `my_sketch`
  - File: `my_sketch.ino`
- This file must contain at least `setup()` and `loop()`.

> Rule: **Folder name = main `.ino` file name** (compared without the extension).

---

## 2. Allowed characters for sketch and file names

Applies to:
- Sketch folder name
- All code file names (`.ino`, `.h`, `.cpp`, etc.)

**Allowed first characters:**
- Letter `A–Z` or `a–z`
- Digit `0–9` (from IDE 1.8.4 onward)
- Underscore `_`

**Allowed following characters:**
- Letters `A–Z`, `a–z`
- Digits `0–9`
- Underscore `_`
- Period `.`
- Hyphen `-`

**Additional restrictions:**
- Maximum length: **63 characters**
- Must **not end with a period** (for example, `test.` is invalid)
- No spaces
- No special characters such as `ä, ö, ü, ß, @, #, $, %, &`, etc.
- No reserved names (the IDE may block some of them)

**Recommendation for robust names:**
- Use only ASCII characters, `_`, and `-`
  Examples: `Blink`, `sensor_test`, `motor-control`, `my_sketch_v2`

---

## 3. File extensions

- Recommended: **`.ino`** (current standard)
- Deprecated but still supported: **`.pde`** (will be removed in the future)
- Other source files allowed in sketches:
  - `.h`, `.hpp` (headers)
  - `.cpp`, `.c` (implementation files)
  - additional `.ino` tabs generated by the IDE

---

## 4. Keeping sketch files together for reliable compilation

- For the most reliable Arduino IDE compilation, keep the main `.ino` file and **all files required to compile the sketch** in the same sketch folder.
- This includes `.cpp`, `.c`, `.h`, and `.hpp` files, plus any file included by source code with `#include` (including embedded HTML files such as `index.html`).
- Do not put a file required by `#include` in `data/` or another subfolder. A quoted include such as `#include "index.html"` is most reliable when `index.html` is beside the source file that includes it.
- Although the IDE supports certain source subfolders, nested layouts can make relative includes and board-specific build behavior harder to diagnose. Use a flat sketch folder when build reliability is the priority.

### `src` – custom code (compiled together)

- not recommended please don't use this folder.
- The folder is searched **recursively** and included in compilation.
- Ideal for larger projects and modularization.
- Typical usage:
  - `my_sketch.ino`: only `setup()`, `loop()`, and calls to functions
  - `src/`: `.h` / `.cpp` files or additional `.ino` files for classes, drivers, and helper functions
- Files included by source code with `#include` must be in a location the compiler can find, such as alongside the including source file in `src/`. For example, if `src/app_httpd.cpp` includes `index.html`, place that file in `src/`, not `data/`.

> Important: The folder name must be exactly `src` (lowercase) so it is recognized correctly across all systems, especially Linux.

### `data` – non-compiled resources

- Use `data/` only for resources that are not needed by the compiler, such as:
  - Configuration files (JSON, TXT)
  - Web assets (HTML, CSS, JS) served or uploaded from a filesystem such as LittleFS or SPIFFS
  - Binary data, fonts, etc.
- Files added via **Sketch → Add File…** are placed here.
- Files in `data/` are not automatically available to C/C++ `#include` directives or uploaded to the board. If a file is included by source code, keep it with the sketch's compilation files instead.

### `extras` – mainly used for libraries

- Primarily used for **libraries** (examples, documentation, tools).
- Not commonly used for normal sketches.

---

## 5. Clean project structure (example)

### Minimal example

```text
my_sketch/
  my_sketch.ino
```

### Recommended structure for larger projects (flat for reliable compilation)

```text
my_sketch/
  my_sketch.ino
  Sensor.cpp
  Sensor.h
  Motor.cpp
  Motor.h
  Utils.cpp
  Utils.h
  index.html
src/            //not recommended
    Sensor.cpp
    Sensor.h
  data/
    config.json
    user_config.json
```

**Structure:**
- `my_sketch.ino`
  - Implements `setup()` and `loop()`
  - Can include local headers and embedded files that are in the same sketch folder
- Other files beside the `.ino`
  - `.cpp` / `.c` implementations, headers, and files referenced by `#include`
  - Keeping these together avoids missing-include errors caused by nested paths
- `data/`
  - Only non-compiled resources, such as files handled separately by a board filesystem upload tool

## 6. Global libraries: locations and structure

Arduino generally distinguishes between:

1. **User libraries** (stored in the sketchbook)
2. **IDE / board package libraries** (stored in installation or hardware directories)

For everyday work, the **user libraries** are the ones that matter most.

### 6.1 Sketchbook folder (base path)

The **Sketchbook folder** can be viewed and changed in the IDE under
**File → Preferences** (Windows/Linux) or **Arduino IDE → Settings** (macOS) as **Sketchbook location**.

**Default paths:**

- **Windows:**
  - `C:\Users\<username>\Documents\Arduino`
- **macOS:**
  - `/Users/<username>/Documents/Arduino`
- **Linux:**
  - `/home/<username>/Arduino`

### 6.2 Library folder (global for the user)

Within the Sketchbook folder, there is a subfolder named:

- `<Sketchbook>/libraries`

This is where the IDE stores:

- Libraries installed via **Sketch → Include Library → Add .ZIP Library…**
- Manually copied libraries as complete library folders
- Libraries installed through the **Library Manager** (in newer IDE versions, these are also stored here)

**Full library paths:**

- **Windows:**
  - `C:\Users\<username>\Documents\Arduino\libraries`
- **macOS:**
  - `/Users/<username>/Documents/Arduino/libraries`
- **Linux:**
  - `/home/<username>/Arduino/libraries`

> Important: The folder must be named exactly `libraries` and must be located directly under the Sketchbook folder, otherwise the IDE will not find the libraries.

### 6.3 Library folder structure (correct installation)

A library must be stored as its own subfolder inside `libraries`:

```text
<Sketchbook>/libraries/
  Adafruit_GFX/
    Adafruit_GFX.h
    Adafruit_GFX.cpp
    library.properties
    examples/
  MyOwnLibrary/
    MyOwnLibrary.h
    MyOwnLibrary.cpp
    library.properties
```

**Incorrect examples:**
- Placing the library directly in `libraries` without its own subfolder
- Nesting multiple levels so that `library.properties` is not located directly inside the library folder

The IDE only searches the **first level** under `libraries`.

### 6.4 IDE and board package libraries (system-wide / per platform)

These folders are usually **not** edited manually, but they are worth knowing about:

- **Windows (IDE 1.x / 2.x, standard installation):**
  - `C:\Users\<username>\AppData\Local\Arduino15\packages\<vendor>\hardware\<arch>\<version>\libraries`
- **macOS:**
  - `~/Library/Arduino15/packages/<vendor>/hardware/<arch>/<version>/libraries`
- **Linux:**
  - `~/.arduino15/packages/<vendor>/hardware/<arch>/<version>/libraries`

These folders typically contain:
- Platform core libraries (for example, `SPI`, `Wire` for AVR/ESP32)
- Libraries bundled with the board package

---

## 7. Practical tips and common pitfalls

- Use **no spaces or non-ASCII characters** in sketch or library folder names.
- Do **not** end a name with a period (`F.O.O.` can cause issues in the IDE).
- For manual library installation:
  - Always copy the **entire library folder** (including `library.properties`) into `<Sketchbook>/libraries/`.
  - Restart the IDE if the library does not appear immediately.
- If you change the Sketchbook path:
  - The library path changes accordingly to `<new Sketchbook>/libraries`.
- For larger projects:
  - Keep the main `.ino` file lean
  - Move logic into `src/`
  - Create libraries for reusable components and store them in `libraries/`
